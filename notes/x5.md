# X5: shell extras (PWA / offline, run history, navigation)

Branch `feat/shell-extras`, from `origin/feat/integration` (5fbc86f).

## What is in place

### PWA and offline

- **`public/sw.js`**: a hand-written service worker, no dependencies.
  - Only same-origin `GET`s are handled. Cross-origin requests, non-GET requests, `Range` requests and
    `/sw.js` itself never reach `respondWith`.
  - Navigations are network first with a 4 s timeout, then the cached page (keyed by pathname: every
    page is static), then a small inline offline page (503) with a link home.
  - `/_next/static/*` is cache first.
  - RSC payloads (`?_rsc=` / `RSC: 1`) are network first, then the cached copy, then an empty `204`.
    Next.js treats a 204 as "nothing usable": a prefetch is retried later and a navigation falls back to a
    full page load, which the SW serves from the cache. This avoids a failed request and a console error.
    It is a deliberate deviation from "stale-while-revalidate for everything else", because a stale RSC
    payload from an older deployment would be served online.
  - Everything else (samples, icons, manifest) is stale-while-revalidate.
  - **Install** precaches `/` and `/workflow` (required; otherwise the install fails and is retried),
    `/templates`, `/batch` and `/history` (best effort: `/batch` 404s until X4 lands, which is fine), the
    three samples, the manifest and the PNG icons. Then it follows every `/_next/static` reference in that
    HTML, in the scripts (Turbopack lists chunks as `"static/chunks/x.js"`) and in the CSS (`url(../media/...)`
    for the fonts). That also caches the data worker, which only starts when a file is added. A page loaded
    once can therefore reload and process a file offline.
  - **Worker scripts**: Turbopack passes a worker's chunk list in the script URL's `#params=` fragment. A
    response from the Cache API carries the cached URL (without the fragment), and the worker then fails
    with "Missing worker bootstrap config". For `destination: worker` requests the SW therefore returns a
    fresh `new Response(body, init)`, which takes the request's full URL. **Keep this** if you touch the SW:
    without it, file parsing breaks online too once the worker script is cached.
  - **New deployments** without a SW change: navigations are network first, so online visits always get
    the latest release. When a fresh page needs static files that are not cached yet, the SW re-downloads
    the other routes too, so the offline copy is one release and not a mix. Static, RSC and runtime caches
    are trimmed (300 / 60 / 60 entries, oldest first).
  - **Versioned caches**: `ewb-{pages,static,rsc,runtime}-<VERSION>`. Activation deletes every `ewb-*`
    cache of another version and calls `clients.claim()`.
- **Update flow** (`components/shell/ServiceWorkerRegistration.jsx`, mounted in `app/layout.js`):
  - It registers only when `process.env.NODE_ENV === 'production'`, after `load`, with
    `updateViaCache: 'none'`. In development it unregisters any worker on the origin and deletes the
    `ewb-*` caches, so `next dev` never serves stale files.
  - A new worker waits; there is no `skipWaiting()` on install. Each open tab shows a sticky
    `toast.info("A new version is available", { action: { label: "Reload" } })` whose description says the
    draft is kept but a loaded file must be added again. Reload posts `SKIP_WAITING`; on `controllerchange`
    that tab reloads (with a 4 s fallback reload).
  - Other tabs are **not** reloaded, because a loaded file lives only in memory. They get "The app was
    updated in another tab" with their own Reload button.
  - The first install's `clients.claim()` is not treated as an update.
  - Updates are checked by the browser on navigation, and here every hour and when the tab becomes
    visible again (at most every 15 minutes).
- **Bump `VERSION` in `public/sw.js`** whenever the SW's behaviour or its precache list changes. Bumping it
  on every release is also fine: it starts the caches afresh and shows the update toast.
- **`next.config.mjs`**: only a `headers()` entry for `/sw.js`, as in the PWA guide: `Content-Type`,
  `Cache-Control: no-cache, no-store, must-revalidate`, and `Content-Security-Policy: default-src 'self';
  script-src 'self'`. The guide's global security headers (`X-Frame-Options` and others) are not added:
  they are outside this task. Vercel applies `headers()` with zero configuration.
- **Manifest** (`app/manifest.js`):
  - `id`, `start_url` and `scope` are `/`, with `display: standalone`, `lang` and `categories`.
  - The theme colour is `--brand` (`#047857`) and the background is `--bg` (`#f5f7f6`).
  - Icons: `public/icons/icon-192.png`, `icon-512.png` (purpose `any`), `icon-maskable-512.png` (full
    bleed, the mark at 78% so it sits inside the safe circle), plus `/icon.svg`.
  - `app/apple-icon.png` (180 px, full bleed, because iOS paints transparent pixels black) and
    `metadata.appleWebApp`.
  - The PNGs are renders of `app/icon.svg` made once with Playwright. Re-render them if the mark changes.
- **Offline indicator**: `components/shell/useOnline.js` (`useSyncExternalStore` on `online`/`offline`)
  and `OfflineIndicator.jsx`.
  - It is a polite live region that is always mounted and empty while online.
  - On phones it drops to its own row under the header bar ("Offline. Files are still processed on this
    device."). From `sm` up it is a pill next to the theme button.
  - The footer says "Once loaded, the app also works offline."
  - Next 16's experimental `useOffline` was not used: it needs `experimental.useOffline` in the config.

### Run history

- **`lib/history.js`**:
  - While anything is subscribed, a `storage` event on `ewb:v1:history` (through `onStorageChange`, which
    also covers `localStorage.clear()` in another tab) drops the snapshot and notifies.
  - After the last unsubscribe the snapshot is dropped, so a change nobody heard is read on the next render.
  - `logRun` and `removeHistoryEntry` always start from what is stored right now, so a tab never
    overwrites runs that another tab logged.
  - `removeHistoryEntry` of an unknown id neither writes nor notifies.
  - The API is unchanged. Tests are in `tests/history.test.js` (new file).
- **Landing**: `components/history/RecentRuns.jsx` sits between "Continue where you left off" and
  "Recent templates".
  - It shows the latest 5 runs with relative time, kind, template name, source file name, and output
    chips with row counts (at most 4 chips, then "+N more").
  - It links to `/history` ("View all N" / "View history").
  - Like the continue card, it renders nothing on the server and nothing when there are no runs; the empty
    state lives on `/history`.
- **`/history`**: `app/history/page.js` is a server page with `metadata.title = "History"`. The client
  component is `components/history/HistoryView.jsx`.
  - The list is grouped by local day ("Today", "Yesterday", then "Saturday, November 7").
  - Each entry shows its clock time and has a remove button. Focus moves to the next remove button, or to
    the h1 when none is left, and the removal is announced.
  - "Clear history" opens a `ConfirmDialog` that states the count, then shows a toast.
  - It has a skeleton until hydration and an empty state with "Start a workflow".
  - It states: "History stores only names, dates and row counts, never data."
- **Helpers**:
  - `components/history/format.js`: kind labels and icons, relative time, day grouping, and
    `outputLabel`, which appends `.fileType` unless the name already ends in an extension.
  - `components/history/hooks.js`: `useHistory`, `useHydrated`, and `useNow`, a shared 30 s clock read
    through `useSyncExternalStore` so that render stays pure.
  - `components/history/RunItem.jsx`.

### Navigation

- `components/shell/SiteHeader.jsx`: Home, Workflow, Templates, Batch, History.
  - From `sm` up, all five are in the bar. The product name appears from `lg`; at `md` it no longer fits
    next to five links and the offline pill.
  - Below `sm`, Workflow and Templates stay visible and Home, Batch and History move into
    `components/shell/NavMoreMenu.jsx`. This is a disclosure (button + list of links, not an ARIA menu)
    with `aria-expanded`/`aria-controls`.
  - Keyboard: Enter / Space / ArrowDown open it on the first link, and ArrowUp opens it on the last.
    Arrows, Home and End move between links. Escape closes it and returns focus. Tab closes it, and so
    does a press outside.
  - The button's accessible name is "More pages", or "More pages, current page: History" on one of its
    pages.
  - The current page has `aria-current="page"` wherever its link is. Only one copy of each link is ever
    displayed.

### Toasts

- `components/shell/Toaster.jsx` renders an optional `action: { label, onClick }`. `lib/toast.js` already
  passes options through, so no foundation change was needed. Pressing the action closes the toast and
  runs `onClick`. Use `duration: 0` for a toast that needs an answer.

## Requests

- **Integrator (CONTRACTS.md §5 Toasts)**: add `action?: { label, onClick }` to the documented toast
  options.
- **Integrator (CONTRACTS.md §11/§12)**: mention `public/sw.js`, the `VERSION` bump rule, and the fact
  that worker scripts must be answered with a fresh `Response` (see above).
- **X3 / X4 (`logRun` callers)**: `outputs[].name` can be either the output name ("Orders") or a file
  name ("Orders.xlsx"). The UI shows a name that already ends in an extension as it is, and otherwise
  appends `.fileType`. For `kind: 'batch'`, a `fileName` such as "4 files" reads well.
- **X4 (`/batch`)**: the route is precached when it exists. Until it is merged, Next's prefetch of the
  header link 404s on this branch (`/batch?_rsc=...`). That is the only console error left, and it goes
  away after the merge.
- **README**: suggested lines are "Works offline once loaded (service worker in production builds)",
  "Bump `VERSION` in `public/sw.js` when the worker changes", and the `ewb:v1:history` key.

## How it was checked

All checks ran against the production build (`npm run build && npx next start -p 3305`) with Playwright
and Chrome. The scripts were not committed.

- **Service worker and offline: 38 checks, all passed.**
  - After the first load the worker controls the page and reports `v1`.
  - There are 3 caches, plus the RSC cache once it is used.
  - `/`, `/workflow`, `/templates` and `/history` are precached; the missing `/batch` is skipped.
  - About 35 static files are cached, including the worker bootstrap, the CSS and the fonts, together
    with the samples, the manifest, the icons and the hashed `icon.svg` and `apple-icon.png`. Nothing
    cross-origin is cached.
  - With `context.setOffline(true)`: `/workflow` opened and reloaded, and the header showed "Offline". The
    sample `.xlsx` was parsed in the worker, mapped with "Map all columns", given an output, and
    **downloaded**. An uncached URL got the offline page, home still opened, and the pill disappeared once
    back online.
- **Update flow.** `VERSION` was bumped on disk while the server ran.
  - After `registration.update()` the toast appeared in both tabs. The new worker waited, the old one was
    still in control, and the toast had a Reload button.
  - Reload: the page reloaded under `v2-test`, every `-v1` cache was deleted, and the new caches were
    filled.
  - The other tab got "updated in another tab" and was not reloaded.
  - An offline reload after the update worked.
- **New deployment with the same worker** (persistent profile, build A, then a rebuild to build B):
  visiting `/` online refreshed the cached `/history` to build B without opening it, and `/history`
  offline ran build B's code.
- **UI: 205 checks, all passed**, at 360 and 1280 px, in light and dark, with the service worker active.
  - The theme follows the OS.
  - Recent runs shows 5 runs, "View all 6", sits before Recent templates, uses relative time, "+1 more"
    and "1,204 rows", and is absent without runs.
  - The footer text is present.
  - On phones: Workflow and Templates plus "More" (40 px). On desktop: all five links. `aria-current` is
    correct on every route, and nav links are at least 40 px. Every keyboard and pointer path of the More
    menu was exercised.
  - On `/history`: the title "History | Excel Workflow Builder", one h1, the privacy statement and 4 day
    groups. Remove updates storage, moves focus and is announced.
  - A run logged in another tab appears live, and clearing in another tab shows the empty state.
  - Clear history: cancel keeps the runs; confirm removes them, shows the empty state and a toast, and
    moves focus to the h1.
  - With the offline pill there is no horizontal scroll. On phones the pill takes its own row; on desktop
    it sits inline to the left of the right-aligned theme button.
  - There was no horizontal scroll on `/`, `/workflow`, `/templates` or `/history`.
  - There were no console errors or warnings apart from the `/batch` prefetch 404 above.
- `npm run lint` (0 warnings), `npm test` and `npm run build` pass.
