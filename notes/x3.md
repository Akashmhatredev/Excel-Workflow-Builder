# X3: Outputs + export extras

Branch `feat/export-extras` (from `feat/integration`). Builds on `notes/agent-c.md`.

## What is where

- `components/outputs/FormattingSection.jsx`: the "Formatting" card in the output editor (between
  the overrides and the preview). Excel sheet switches (bold header, freeze header, filter buttons;
  `sheetStyle` is merged here because the store replaces it) and the highlight rules: column
  (`getResultColumns`), condition (`CONDITIONAL_OPERATORS` with `FILTER_OPERATORS` labels, 0/1/2
  value inputs by arity), colour, bold, move up/down (focus follows), remove. A rule whose column the
  output no longer has is marked invalid (red select, message, "N rules to fix" badge).
- `components/outputs/HighlightPicker.jsx`: radio group of `HIGHLIGHT_STYLES`, each with a sample
  cell, its name and a check mark when chosen (not colour alone); arrow keys like `Segmented`.
- `components/outputs/LogoField.jsx` + `logo.js`: logo upload, height (16 to 120 px), Replace, Remove.
- `components/export/runLog.js`: `recordRun(kind, outputs)` wraps `logRun` with the store's
  `templateName` and `file.name`. Called after each successful file, zip, PNG and PDF download.
- `helpers.js` gained `describeConditionalFormat(rule, resultColumns)` and `visibleHighlights`.

## Behaviour and assumptions

- CSV outputs: the rules editor stays visible, under a notice that CSV cannot carry formatting and
  that the rules stay saved. The sheet switches are hidden for CSV.
- Highlights: `data.highlights ?? []` everywhere. The output preview passes the tuples inside the
  shown rows to `DataTable cellMarks`. I keep only the **first tuple per cell**, because X2's DataTable
  keeps the last one while ReportView keeps the first. ReportView and the Export capture get the same
  tuples.
- ReportView: light and brand themes use the Excel colours as they are. The dark theme uses a 50% tint
  of the text colour towards the table with the light fill as text (8.5:1 or more), falling back to
  the Excel pair below 4.5:1. The logo sits left of the title, and the title block wraps under it when
  less than 240 px is left. Logos are drawn only when they match the schema's data-URL pattern.
- Logo: the type is checked from the name/MIME type and then from the **file's first bytes**, so SVG,
  GIF and an SVG renamed `.png` are all rejected with a message. The image is drawn at most 360 px tall
  (3 x the 120 px maximum) and 1440 px wide, never enlarged. It is encoded as WebP 0.92, then PNG, then
  WebP 0.8, and shrunk by the square root of the overshoot until it fits `REPORT_LOGO_MAX_CHARS`.
- PDF: "Fit to image" makes the page exactly the image (margin 0). "A4" puts the image on one A4 page
  with a 28 pt margin, in landscape when the image is wider than tall, and never scales it up. The
  `pixelRatio` is the measured image px per CSS px, so a reduced-scale tall capture still sizes right.
- History: `kind` file/zip/image/pdf. For PNG and PDF, `fileType` is `png` / `pdf` and `rowCount` is
  the number of rows in the picture. For zip, `fileType` comes from each entry's extension.

## Changes to my lib files (additive)

- `lib/share.js` `nodeToPngBlob`: it now waits (up to 3 s) for the `<img>` elements inside the node
  to decode, and measures the size after fonts and images have settled.
- `lib/pdf.js`: `pdfString` is exported. A non-ASCII title (₹, Devanagari) is written as a UTF-16BE
  hex string instead of `?`.

## Verified (production build, Chrome via Playwright, real sample files)

There were 33 scripted checks. They covered:
- the sheet style merge;
- add, edit, reorder and remove rules, with the operator list, arity inputs, arrow keys and focus;
- an invalid column, and the CSV notice;
- SVG, renamed-SVG and GIF rejection;
- a 3.2 MB noise PNG shrunk to 84k chars of WebP, and a 900x300 logo stored as an 11 KB WebP;
- the logo height, and the logo plus highlights in the live preview and in the capture;
- the PNG, and PDFs (fit and A4) that are structurally valid, with every xref offset checked;
- the single file and zip downloads, and the `ewb:v1:history` entries;
- 360 px with no horizontal scroll, and no console errors.

Both PDFs render with macOS `sips`, and the A4 one opens in Chrome's PDF viewer with the right title.
Highlights came from a stand-in that wraps `Worker.onmessage` and adds tuples. With X2's DataTable
temporarily checked out, the preview table coloured 14 cells. That file was reverted, not committed.
