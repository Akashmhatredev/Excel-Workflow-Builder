# X2: Upload + Mapping extras UI

Branch `feat/data-ui-extras` (from `feat/integration`). Only my files changed, plus one new test file.

## What is built

- **Merge columns from a second file** (`components/upload/LookupCard.jsx`, `LookupSettings.jsx`, `lookup.js`):
  a collapsible card on the Upload step, shown once the main table is loaded (and after a failed reload, so a
  merge that broke the table can still be removed). Collapsed by default; it opens by itself when a lookup is
  configured, a lookup file is loaded or the template expects one.
  - Own drop target (`data-lookup-drop`) and file picker -> `loadLookupFile`. UploadStep ignores drags and drops
    inside it, so a file dropped there never replaces the main file.
  - File row (name, size, rows x columns, Replace, Remove -> `clearLookup`), read error with "Choose another file".
  - Sheet select (`setLookup({ sheetName })`), header row committed on blur / Enter (`setLookup({ headerRow })`).
  - "Match rows where [column of this file] equals [column of the second file]". Lookup-origin columns are not
    offered on the main side. A one-click suggestion uses a column name both files share (identifier-like names
    first) or fills in the missing half of a pair.
  - "Columns to bring in" checklist (`columns`, `[]` = all except the key; the last ticked one cannot be unticked).
  - Result from `lookupInfo`: "Matched 280 of 300 rows", rows without a match, duplicate keys, the added columns;
    "Merging the files…" while busy; "Nothing was merged" when the join is configured but `lookupInfo.applied`
    is not true.
  - `selectLookupNeeded`: a notice in the card (names the key and expected columns, "Skip the merge"), a notice on
    Upload before the main file is loaded, and one on Mapping ("Add it in Upload"), because applying a template
    with a file already loaded lands on Mapping.
  - Detected columns show a "lookup" badge (icon + text) for `origin === 'lookup'`.
- **Data cleaning** card between Filters and Group (`components/mapping/CleaningEditor.jsx`,
  `FieldChecklist.jsx`, `cleaning.js`), bound to `definition.cleaning` / `setCleaning` (undoable, coalesced by the
  store). Trim spaces, remove empty rows, remove duplicates (whole row or chosen fields), fill blanks (fixed value or
  row above; every field or chosen fields). It shows `preview.data.stats`: "In the whole result: 12 duplicates
  removed, 4 blanks filled."
- **DataTable** (additive props):
  - `cellMarks?: [row, col, tone, bold?][]`, indexed once into `Map<row, Map<col, mark>>`. `'error'` gets the
    danger tint, a corner triangle and a screen-reader "(error)"; `'blank'` gets a hatched pattern and "(blank)";
    a `HIGHLIGHT_STYLES` key gets that fill and colour. `bold` makes the cell semibold. When one cell is marked
    twice an error wins.
  - `totalsRow?: boolean`: the last row is rendered outside the virtual list as a sticky footer (bold, top rule, Σ
    in the gutter).
  - `totalsColumn?: boolean`: the last column is bold with a rule on its left.
- **Result panel** (`components/mapping/ResultPanel.jsx`): ARIA tabs "Preview | Summary" (arrow keys, Home, End),
  replacing the old "Live preview" card. Only the open tab is mounted.
  - Preview (`PreviewPanel.jsx`): "Highlight problems" switch feeding `cellIssues ?? []` into `cellMarks`, plus a
    legend with counts (counted in the rows shown).
  - Summary (`components/summary/*`): rows / columns (optional) / calculate / of, `runPivot` debounced 250 ms and
    re-run on definition, `dataVersion` and setting changes (`usePivot.js`). A DataTable with `totalsRow` and
    `totalsColumn`, notes for groups beyond `limit` and `truncatedColumns`, an error notice with "Try again", empty
    states for no file and no fields, and "Download as CSV" (UTF-8 BOM, RFC 4180, built from the display strings,
    `downloadText`, then `logRun({ kind: 'file' })`).
- `tests/data-ui-extras.test.js`: CSV quoting, pivot settings, the cleaning stats text and the lookup helpers.

## Assumptions

- `runPivot`: the last row is always the totals row. The last column is styled as totals only when there are more
  than two columns, because with no column field the single value column may itself be the total. `totalRows` is the
  number of row groups, not counting the totals row. The CSV has exactly what is shown.
- The pivot settings and the highlight switch are local UI state, not part of the definition (no schema shape for
  them). They survive a tab switch but not leaving the step.
- The lookup key pair is only sent to the store once both columns are chosen (each `setLookup` re-reads the main
  table); a half-chosen pair is a local draft. Clearing one side of an applied pair is sent, so the join switches off.
- The lookup is not in undo history (store design: undo keeps `definition.lookup`).
- A runPivot failure is shown inline instead of a toast; a debounced auto-run would otherwise toast on every edit.

## Not verified without X1's engine

In this worktree the worker returns no `stats` / `cellIssues`, ignores `lookup` (`lookupInfo: null`) and rejects
`runPivot` ("Unknown request"). Against the real build I checked the fallback states: "Nothing was merged", no
stats line, an empty legend (0 errors, 0 blanks) and the pivot error notice with "Try again". The rendering of real
results was checked only with faked worker responses in a scratch Playwright script (not committed): the lookup
summary and badges, the cleaning stats, the error and blank marks in both themes, the pivot table with the sticky
totals row, the truncation notes and the CSV download. All at 1360px and 360px, with no page-wide horizontal scroll.
