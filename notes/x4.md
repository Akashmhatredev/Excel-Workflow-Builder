# X4 (templates, batch mode, sharing, aliases): notes

Branch `feat/templates-extras`, on top of `origin/feat/integration` (5fbc86f).

## What is built

- **Tags and folders.** `components/templates/TagInput.jsx` (chips; Enter or a comma adds, a pasted
  "a, b" adds both, leaving the box adds what was typed, each chip has a remove button; `normalizeTags`
  limits) and `TemplateMetaFields.jsx` (Tags + Folder with datalists of the tags/folders already in
  use). Both are in the Save-as-template dialog (pre-filled from the linked template) and in the new
  **Edit details** dialog (`EditDetailsDialog.jsx`: name, description, tags, folder), which replaces
  the card's Rename modal. Cards show the folder above the title and the tags as badges.
- **Templates page.** Folder filter (`All folders` / each folder / `No folder`, with counts), tag
  toggle chips (`aria-pressed`; several selected = the template needs all of them), combined with the
  search, which now also matches tags and folders. With "All folders" the list is grouped by folder
  (named folders A-Z, then "No folder"). "Clear filters" and an empty state for no matches.
- **Share links.** Card action "Copy share link": builds the link, copies it straight away, then
  shows it in a dialog (Copy again, character count, "nothing is uploaded" notice, a long-link warning
  above `SHARE_URL_WARN_LENGTH` with an "Export as JSON" fallback). `/templates#template=...` opens
  "Import shared template?" (name, description, folder, tags, field/output counts, the name it will get
  if it clashes, warnings) or "This share link could not be opened" with the reasons.
  **QR codes are out of scope**: a template link is usually 2,000+ characters (often far more with a
  report logo), well beyond what a phone camera reads reliably from a screen.
- **Batch mode** at `/batch` (`app/batch/page.js` server page with `metadata = { title: "Batch" }`;
  client part `components/batch/BatchView.jsx`, `FileQueue.jsx`, `BatchResults.jsx`, `format.js`).
  Template picker (grouped by folder, plus "Current workflow" when the wizard's definition has fields
  and outputs; `?template=<id>` preselects one: the card's "Run on several files" action), multi-file
  input + drop zone with a removable queue (spreadsheets only, no duplicates, at most 50), progress
  (file i of n, phase, progress bar, Stop), a summary and a per-file table (sheet read, rows, outputs
  with row counts, missing columns with a link to the aliases section, warnings, errors), then
  "Download zip" (`downloadBytes`) which calls `logRun({ kind: 'batch', templateName,
  fileName: '<n> files', outputs })` once per run (outputs = the definition's outputs with row counts
  summed over the files). Empty state when there are no templates and no usable workflow.
- **Column aliases** (`components/templates/AliasManager.jsx`): a collapsible "Column aliases" card on
  the Templates page (opens by itself at `/templates#column-aliases`). Lists the pairs with Remove,
  "Add alias" form (column-name suggestions from the templates' expected columns), inline validation,
  and a toast on a storage failure (`notify.js` got an aliases-specific "storage is full" text).

## Library changes (please fold into CONTRACTS.md sections 2, 10 and 12)

- **`lib/aliases.js`** (now X4's; section 2 still lists it under the foundation):
  - `saveAlias(from, to)` -> `{ ok, aliases, existed?, code?, error? }`. Empty names, the same name twice
    and more than `MAX_ALIASES` (500) return `ok: false, code: 'invalid'`; storage failures return the
    storage `code`. A pair that already exists *in either direction* is not stored twice (`existed`).
  - `removeAlias(from, to)` removes the pair in either direction, same result shape.
  - New: `isSameAlias`, `ALIAS_MAX_LENGTH` (120), `MAX_ALIASES`, and `subscribeAliases` /
    `getAliasesSnapshot` / `getServerAliasesSnapshot` for `useSyncExternalStore` (also follows other tabs).
  - `loadAliases()` now cleans what it reads (trims, drops junk and reverse duplicates).
- **`lib/batch.js`**: `runBatch` also takes `signal` (AbortSignal); progress is
  `{ index, total, fileName, phase: 'reading'|'loading'|'building'|'zipping', outputName?, outputIndex?, outputCount? }`;
  the result adds `cancelled`, `summary { files, succeeded, failed, withMissingColumns, outputs }`, and per
  file `warnings` (missing sheet, table warnings), `sheetNames`, `skipped`, and `outputs[].{ outputId, name, fileType }`.
  It rejects up front when there are no files or no outputs; a failing output no longer fails the
  whole file; file names in a folder are made unique; `.zip` is appended when missing; runs are
  queued so two batches never share the `"batch"` dataset. New exports `BATCH_ACCEPT`,
  `BATCH_MAX_FILES`, `isSpreadsheetFile`.
- **`lib/shareLink.js`**: `createTemplateShareUrl(template, origin)` -> `{ url, length, tooLong }`,
  `readSharedTemplate(payload)` (never rejects; `parseTemplateJson` result), `hashWithoutSharePayload(hash)`.
  Decoding tolerates line breaks and trailing punctuation that chat apps add; `readSharePayload`
  accepts a percent-encoded `=`.
- **`lib/templates.js`**: `NO_FOLDER`, `templateFolders`, `templateTags`, `filterTemplates`, `groupTemplatesByFolder`.
- **`TemplateCard`** props: `{ template, showFolder = true }`.

## Deviations

- "Rename" on the card became "Edit details" (it still renames).
- The zip is downloaded with a button after the run, not automatically: the user sees warnings first
  and the download is never blocked as a non-gesture download.
- Stop sits in the progress panel, not in place of the Run button: in the browser check a Stop click
  that landed just as a run ended hit Run and started a new batch.
- The shared-template dialog keeps the decoded result in state and removes the hash as soon as the
  link is read. Next.js applies `history.replaceState` through its router a moment later, and a hash set
  in between was overwritten (seen as a flaky check), so the dialog must not depend on the hash.
